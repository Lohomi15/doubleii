# doubleii — Safari Extension

This directory contains everything needed to build doubleii as a Safari Web Extension for macOS.

Safari Web Extensions require a thin macOS app wrapper generated by Xcode. The `build.sh` script automates that step.

---

## Prerequisites

- macOS 14.0 or later
- Xcode 14 or later — [Download from the Mac App Store](https://apps.apple.com/app/xcode/id497799835)
- A free Apple ID (no paid developer account required for local / sideload use)
- The doubleii repo cloned locally

---

## Build & install

**Step 1 — Generate the Xcode project**

```
chmod +x safari/build.sh
./safari/build.sh
```

This runs `xcrun safari-web-extension-converter` which wraps the existing Chrome extension source into an Xcode project at `safari/doubleii/`. It does not modify any of your extension source files.

**Step 2 — Open the project in Xcode**

```
open safari/doubleii/doubleii.xcodeproj
```

Or double-click the `.xcodeproj` file in Finder.

**Step 3 — Build and run**

- Select the `doubleii (macOS)` scheme in the scheme picker.
- Press `Cmd+R` (or Product > Run).
- The thin wrapper app launches. You can quit it immediately after — it only needs to run once to register the extension with Safari.

**Step 4 — Enable in Safari**

1. Open Safari > Settings (Cmd+,) > Extensions.
2. Find "doubleii" in the list and tick the checkbox to enable it.
3. When prompted, click "Allow" for the extension to run on all websites.
4. If you don't see doubleii, go to Safari > Settings > Advanced and tick "Show Develop menu in menu bar", then Develop > Allow Unsigned Extensions. You may need to re-enable this after each macOS restart while sideloading.

## Smoke test checklist

Run through these after enabling the extension:

- [ ] Open any article (e.g. https://en.wikipedia.org/wiki/Anthropic).
- [ ] Highlight a sentence — the doubleii tooltip button should appear.
- [ ] Click the button — the explanation panel should open and stream a response.
- [ ] Press Alt+B (Option+B on Mac) with text selected — same result via keyboard shortcut.
- [ ] Right-click selected text — "Explain with doubleii" should appear in the context menu.
- [ ] Open extension options: Safari > Settings > Extensions > doubleii > Preferences. Enter an API key and save.
- [ ] Reopen options — verify the key persisted.
- [ ] Open the history panel from options — verify previous explanations appear.

## Known limitations vs Chrome

**Font loading in Shadow DOM**
The extension injects a Shadow DOM panel styled with a custom font loaded via `chrome.runtime.getURL()`. On Safari 16 some builds silently drop `@font-face` loads from `safari-extension://` URLs inside dynamically injected shadow roots. The fallback font stack (`-apple-system, BlinkMacSystemFont, sans-serif`) will engage automatically, so the panel will not break — it will just use the system font. Test with Safari Web Inspector (Develop > Show Web Inspector, then the Timelines or Console tab) to confirm whether the custom font loads on your Safari version.

**Keyboard shortcut rebinding**
Chrome lets users remap extension shortcuts at `chrome://extensions/shortcuts`. In Safari, shortcuts are remapped via Safari > Settings > Extensions. The tooltip in the extension UI refers to "Alt+B" which is accurate on macOS (Option+B), but there is no in-extension link to the remapping UI.

**"Allow Unsigned Extensions" resets on restart**
When sideloading (no Apple Developer account), macOS resets the "Allow Unsigned Extensions" flag after each restart. Re-enable it via Develop > Allow Unsigned Extensions in Safari.

**`options_page` key**
The manifest uses `options_page` (MV2-style) which Safari 17+ supports via compatibility shim. It works, but future Safari releases may require migrating to `options_ui` with `open_in_tab: true`.

## Distribution

**Personal / sideload use**
Build and run locally as described above. No Apple account required beyond a free Apple ID.

**Mac App Store**
Requires an Apple Developer Program membership ($99/year). In Xcode: set your Team under Signing & Capabilities, archive the app (Product > Archive), and submit via Xcode Organizer. The extension and wrapper app are submitted together as a single Mac App Store app.
